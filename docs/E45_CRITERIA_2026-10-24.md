# E45 criteria (FROZEN 2026-10-24, before any E45 training row is generated)

## Question

E44 (result cddd417) made the model use the text: the threshold now drives the
answer (probe S 0.92–0.98, magnitude L/H 1.00) and the goal moved (swap
0.12 → 0.54 / 0.77). Two things did not follow:

1. **Fine comparison.** Bind dev accuracy falls with the relative gap
   (≥ 50 % 0.98, < 10 % 0.50–0.74), and the probe's T condition (the total
   stated in the text, original fine gaps) stays at 0.55–0.62: two numbers
   written in the text are not compared at the digit level either. E44 pairs
   were mostly coarse (median gap ≈ 1.5×).
2. **Goal negatives.** E44 drew negative goals with token Jaccard < 0.5, an
   easier distribution than "any other episode's goal".

E45 asks: starting from the E44 checkpoints, do fine-gap data, digit-reading
and text-only comparison targets, and unfiltered plus multi-choice goal
negatives close both gaps, still without regression against the released
E41 model?

Design choices come from E44's bind dev (selection data) and the probe (dev),
not from the E44 gate sets. The E43 swap set (M3) and the E38a test (M2) were
gates in E44 and are gates again; they are not used for selection.

## Arm (one arm, two seeds)

- Init: the E44 selected checkpoints (s42 bb4f659f…, s43 59b1cd82…), read from
  the output of kernel `gjusev/mkshv-e44-train`, sha-verified.
- E44 recipe unchanged (800 steps, slot % 4: 0 synthetic, 1 E41 real, 2 bind,
  3 replay; AdamW 2e-5 / 1e-4, wd 0.01, warmup + decay, fp16, 1024 px,
  700/96 tokens). A bind microbatch holds two whole pairs of one kind.
- Dev every 200 steps; selection as E44 (mean of synthetic dev-half macro,
  real-dev macro, bind-dev accuracy; tie → synthetic dev-half accuracy).

## Bind pool v2 (generated by `scripts/gen_e45.py` after this commit)

Same images as E44 (E38a field_threshold, E41 CORD and GUI train; probe
documents and their counterfactual siblings excluded), new rows. Weights:

| kind | weight | construction |
|---|---|---|
| num_syn | 0.20 | E44 pairs (same image, threshold total/g true, total×g false), gap g log-uniform in [1.002, 1.10] for 70 %, [1.10, 1000] for 30 % |
| num_cord | 0.10 | same on CORD receipts, IDR format |
| cmp_text | 0.15 | text only (no image): state "The total printed on this document is {t}." (probe T sentence), field_threshold question; totals log-uniform 1–100,000 EUR (row language format) or 1,000–5,000,000 IDR; same gap schedule; 5 % of pairs use thr = total (gold true) against thr = next unit up (gold false) |
| digits | 0.20 | image, singletons grouped two per slot: first digit of the total (options 1–9), second digit (0–9), number of digits of the integer part (1–7); one question per image, rotated |
| range | 0.05 | E44 RANGE family |
| goal | 0.15 | final screen with own goal (true) vs another train episode's goal drawn uniformly (no similarity filter) (false) |
| goal_match | 0.15 | final screen, "Which goal does this screenshot show as completed?", four options = own goal + three other train goals (uniform), own goal at a deterministic random position; singletons grouped two per slot |

Dev (selection only): the same constructions on dev images and dev episodes.

## Measurements and baselines

Same sets and pipelines as E44 (M1 probe, M2 E38a field_threshold test,
M3 E43 swap + own goal, M4 E38c CORD, N1 synthetic test non-FR, N2 E38c GUI,
N3 testC / task). Reported without gate: probe O and T, digits dev, cmp_text
dev, goal_match dev, bind dev by gap bucket.

## Success rules (fixed here; same thresholds as E44)

- **G1 numbers**: both seeds: probe SYN S ≥ 0.50, L and H ≥ 0.90, and
  M2 ≥ 0.70.
- **G2 goals**: both seeds: M3 swap ≥ 0.80 and own goal ≥ 0.80.
- **G3 no regression, against the released E41 checkpoint of the same seed**:
  N1 drop ≤ 2.0 pp, N2 drop ≤ 3.0 pp, N3 drops ≤ 3.0 pp each.

G1 + G3 or G2 + G3 → that capability is a release candidate, pending a
recalibration experiment (E42 protocol, new criteria). Otherwise reported as
measured. E45 changes no public number by itself.

## Budget and guards

T4×2, smoke 20 steps first; train deadline 2.5 h, wall kill 3.2 h (E44 took
2.6 h wall at the same step count). Launch only with the user's GO.
