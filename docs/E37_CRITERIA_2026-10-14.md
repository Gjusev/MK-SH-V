# E37 criteria (FROZEN 2026-10-14)

E37 answers one question: **can NeoMME-260M carry the MK-SH decision head on
the hardware we have, without losing the text capability MK-SH-1 already has?**

Frozen before any criterion measurement (C1-C4). The only Kaggle run before
this freeze was the environment preflight (kernel `gjusev/mkshv-e37-preflight`
v2, `runs/e37-preflight/env.json`): versions, GPU, model/processor load and
layout smoke — no training, no marker resize, no accuracy number. After
freezing, thresholds and outcomes below do not change; a new experiment
number is needed for anything else.

## Pins (measured in the preflight, 2026-10-14)

- NeoMME-260M revision SHA: `5ba79fb246e23776d2c2fcead975eae2775ed94b`
- transformers: 5.19.0 (>= 5.17 required; installed fresh in-kernel)
- torch 2.11.0+cu128 (CUDA 12.8), Pillow 12.3.0, Python 3.13.15
- Kaggle GPU: Tesla T4 x2, 14.56 GB per GPU; every stage uses ONE GPU (cuda:0)
  on the `NvidiaTeslaT4` shape (T4x2 consumes quota at double rate)
- mokka-decisions commit: `9e1a226e` (installed from
  `git+https://github.com/Gjusev/MK-SH-1@9e1a226e` in-kernel; local install
  verified byte-identical)
- MK-SH-1 reference: Hub `Gjusev/MK-SH-1`, weights sha `ea66cdde...` (v1.1 =
  v1.2 weights); reference numbers are the frozen E35 s42 report, not re-run
- NeoMME tables at load: word (131072, 256), value (131072, 256), hidden 1024,
  full-attention layers at indices 5/11/16, patch 32, context 16384
- Synthetic generator: `src/mksh_v/synth_doc_type.py` at the commit that
  freezes this file; kernels embed it via `kaggle/build_kernels.py`

## Shared training pins (C1, C2, C4)

- Optimizer AdamW groups (encoder 2e-5, head 1e-4), weight decay 0.01,
  grad-norm clip 1.0, fp16 autocast + GradScaler, warmup 5 % of the run's
  optimizer steps, LR lambda `max(0.05, 0.95*(1-progress)+0.05)`, seed 42.
- Effective batch 32 = microbatch x accumulation (accumulation adjusted so the
  product stays 32).

## C1. Hardware compatibility

Kernel `gjusev/mkshv-e37-c1`. On one T4 (cuda:0), 100 optimizer steps of A1-V
on synthetic doc_type data (512 cases over the 12 train templates, seed 42) at
image longest side 768, 1024 and 1536 px; fresh model per size. Microbatch
search: start 8, halve on OOM probe (one forward/backward), floor 1. Timing =
mean wall seconds per full optimizer step (forward+backward+update, CUDA
synced), steps 10-99 (first 10 excluded). Records peak allocated/reserved
memory, loss finiteness at every step, and the account quota counter before
and after (read locally via the Kaggle MCP, recorded in `docs/status.md`).

- **Pass**: at least one image size runs 100 steps with finite loss and fits
  in one T4 (14.56 GB). Otherwise: try P100 FP32 at 768 px; if that fails
  too, outcome STOP-A1.

## C2. Marker tokens

Kernel `gjusev/mkshv-e37-c2`, image size 768, microbatch from the C1 run at
768 px. Checks:

- **A resize**: 32 `[O_i]` tokens added; vocab grows 131072 -> 131104 in
  config AND in both factorized tables (word, value); marker ids distinct.
- **B gradients**: one backward on 4 image cases; marker rows of BOTH tables
  receive nonzero gradients.
- **C distinctness**: marker hidden states of one case's 6 options are
  pairwise distinct (min pairwise L2 > 0).
- **D overfit**: 200 cases, up to 40 epochs at effective batch 32; pass when
  train accuracy >= 0.95 at some epoch AND last-epoch mean loss < first-epoch
  mean loss.
- **C2 pass** = A and B and C and D. If resizing were unsupported, the pinned
  fallback is existing reserved/rare tokens as markers (documented); the
  preflight showed resizing is implemented, so the fallback is not expected.

## C3. Text parity (the gate)

Kernel `gjusev/mkshv-e37-c3`, dataset source `gjusev/mokka-decisions-bundle`.
NeoMME + marker head, TEXT ONLY, with the MK-SH-1 v1.1 recipe (E35 stage,
seed 42, one shot, no retries):

- Mix per phase: E35 extremes grid (248) + standard grid replay (944,
  `e28-ext/train_rows.jsonl`) + original task replay (944, e29-mix manifest
  `original_train_ids` from `data/processed/v1/instances/train.jsonl`).
- 3 phases x 5 epochs; fresh AdamW per phase; microbatch 8 x accumulation 4;
  shuffle rng seeded `42 ^ 0xE35 ^ phase` per phase, reshuffled per epoch.
- Sequence: A1-V tail `state <eos> question [Oi] option_i`, state capped at
  700 tokens, option descriptions at 96 (declared divergence: E35 used
  julia_sequence budgets 1024/256; rows otherwise verbatim — E35 re-dumped
  noul states, whitespace-equivalent).
- Eval at t0 and after each phase on the frozen sets: known = testC (48),
  new = testD (54), mono (60), e = testE (202) with the `thr_range ==
  "extrap"` slice reported as E-extrap (56), task = e29-mix dev ids (300).
  Final-checkpoint numbers decide the gate.
- MK-SH-1 v1.1 references (frozen, not re-run): testC 0.979, task 0.800,
  E-extrap 0.875.

**Decision rule (project thresholds, fixed now):**

- NeoMME within 5 pp of MK-SH-1 on testC **and** task: **GO-A1**
  (testC >= 0.929 and task >= 0.750).
- Worse than that on either: **GO-A2** (hybrid becomes primary).
- One seed is enough for this gate; it is a routing decision, not a claim.
  The result is reported as exploratory.

## C4. Visual smoke

Kernel `gjusev/mkshv-e37-c4`. A1 on synthetic doc_type: 2004 train cases over
12 templates (2 per class), 402 dev cases over 6 held-out templates (1 per
class, `stratified_template_split`), seeds 42/43, majority rate 1/6. Training:
500 optimizer steps, effective batch 32, shared training pins, image size
1024 if C1 passed at 1024 else 768. Swap test: dev cases evaluated with images
rolled by one (every case gets a foreign dev image).

- **Pass**: dev accuracy > majority rate (1/6) AND swap accuracy <= majority
  + 0.03. If swapping does not hurt, the generator leaks the label through
  text and must be fixed before E38 (that would be a C4 FAIL regardless of
  accuracy).

## Outcomes

`GO-A1`, `GO-A2`, or `STOP-A1` (hardware or marker failure), each with the
evidence files listed in `docs/status.md`:

- STOP-A1 iff C1 fails everywhere (T4 fp16 and P100 fp32) or C2 fails.
- GO-A2 iff C1+C2 pass and C3 misses the 5-pp window.
- GO-A1 iff C1+C2 pass and C3 holds the window. C4 does not route A1 vs A2;
  a C4 fail blocks E38's generator reuse, not the backbone choice.
