## Question

E47 (result 6c5f6db) met the numbers gate on both seeds: synthetic
field_threshold test (M2) 0.725 / 0.718 against 0.70, probe S 0.879 / 0.820,
L and H at least 0.94, no regression against E41 on exact counts. E47 itself
named three limits: the margin is inside the binomial noise of 600 cases
(±3.6 pp), M2 has been read as a gate four times (E44 to E47), and the gain is
not explained by the per-position digit reading.

E48 answers two questions before any release decision, with no retraining:

1. **Does the numeric result hold on documents nobody has read?**
2. **Do the E47 checkpoints keep a claimable abstention set under the E42
   protocol, with the U1024 input rule?** The released E41 model claims the
   synthetic test non-FR set. A replacement that loses that claim does not
   replace it.

## Fresh numeric set (generated by `scripts/gen_e48_fresh.py` after this commit)

- Generator: the frozen `mksh_v.gen_e38a.generate_split("field_threshold",
  "test", lang, seed=S)`, unchanged, rendered with the E38a renderer (same
  fonts, Playwright/Chromium).
- Seeds S = 4801, 4802, 4803, 4804, 4805; languages EN, ES, DE; 200 cases per
  seed and language, so 3,000 rows. The test templates are the same five as
  M2's, by construction, so the set has M2's distribution.
- Ids, group ids and counterfactual base ids are renamed from `e38a-` to
  `e48s{S}-` so no id collides with E38a.
- Declared overlap, by construction: the generator derives the visual theme
  from the group id, not the seed, so group g of every fresh seed shares its
  theme (fonts, colours, spacing) with group g of the original test split.
  Content, totals, thresholds and the template draw come from the new seed.
  An image byte-identical to any E38a image aborts the generation.
- This set is never used for training, selection, temperature, threshold or
  any other choice. It is read once, by the kernel below.

## Protocol (E42 verbatim unless stated)

- Per seed: evaluate option probabilities on cal_temperature, cal_policy,
  test non-FR, test FR, CORD, GUI, testC, task and the fresh set, with the
  U1024 input rule on every image (`upscale_to = 1024`, `max_side = 1024`).
- T fitted on cal_temperature (frozen NLL grid 0.50–3.00 step 0.01 plus ternary
  refinement); τ = the smallest value on {0.30, 0.35, …, 0.95} whose cal_policy
  CP95 upper bound of selective risk is ≤ 0.05; none → τ = 0.95,
  `met_target: false`.
- Held-out tables with exact two-sided Clopper-Pearson 95 %, budget judged on
  the upper end; per-family sub-tables for test non-FR and FR; risk-coverage
  curves; ECE15 and NLL raw and at T.

## Rules (fixed here)

- **C1, numbers confirmed**: raw accuracy on the fresh set ≥ 0.70 for both
  seeds. The CP95 interval is reported next to it.
- **Claim rule (unchanged from E42)**: a held-out set is claimable iff its
  CP95 upper bound at τ is ≤ 0.05 for both seeds. Claims never use cal splits.
- **Release rule**: the E47 checkpoints may replace E41 in the public release
  only if C1 holds and synthetic test non-FR is claimable. Even then the
  release is a separate decision by the user. If C1 holds, the public line
  "printed numeric thresholds are not a capability" is rewritten to state the
  fresh-set accuracy; if it fails, it stays. The goal claim stays at
  "end-of-task screen detection" whatever happens here (E47 G2 not met).
- Everything else is reported as measured; no post-hoc re-tuning on any
  held-out set.
