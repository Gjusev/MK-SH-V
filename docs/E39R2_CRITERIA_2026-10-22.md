# E39-r2 criteria (FROZEN 2026-10-22)

E39-r2 re-runs ONLY the two reported (non-gate) comparators of E39, which
did not produce valid results in v7: SmolVLM2-500M (task-trained) was
`not_run` and jev-vlm-4b (zero-shot) produced no valid output. Their
protocol is the one frozen in `docs/E39_CRITERIA_2026-10-14.md`; E39-r2 only
fixes the implementation defects below. **E39's gates and verdict do not
change and nothing here is re-tuned against E39's results**: A1-V and
OCR→MK-SH-1 are not re-run; their official per-case files from E39 v7 are
the reference.

## Defects fixed (evidence: v7 logs/files, reviewed 2026-10-22)

SmolVLM2 (`SmolScorer` / `run_worker`, `kaggle/e39_train.py`):
1. Prompts lacked the `<image>` placeholder the SmolVLM processor requires
   (v7: `ValueError: The number of images in the text [0, 0, 0, 0] and
   images [4] should be the same`). Fixed: one placeholder per image; images
   passed per sample.
2. Latent: answers were read at the last position (`logits[:, -1]`) with
   RIGHT padding, i.e. at a pad token for every row but the longest in a
   batch. Fixed: left padding.
3. Latent: the SmolVLM2 model was never put in train mode (HF loads in eval
   mode; the loop only called `.train()` for the other arms) → trained
   without dropout. Fixed: train mode during training, as for the other arms.
4. Equal visual budget: images are capped at longest side 1024 px (A1-V's
   E39 size) instead of the processor default 2048 px.

jev-vlm-4b (zero-shot): the model is a pointer-head decision model with no
`.generate()` (v7: `AttributeError` on every row). Fixed: its documented API
`model.decide(processor, state, questions, images)` at the pinned revision
`8c56e46a`, fp16 (T4 has no bf16). Mapping: cases whose option ids are
exactly {false, true} → `noul` (P(true) from `probability`); all others →
`choice` with `criteria = {option_id: description}`; question text →
`instructions`; case state → `state`; image capped at longest side 1024 px.
A row whose input the model rejects (e.g. its token cap) is recorded as
unanswered with the error, counted in coverage, never dropped silently.

## Protocol (unchanged from E39 except the fixes)

- SmolVLM2: id/revision pinned (`HuggingFaceTB/SmolVLM2-500M-Video-Instruct`
  `7b375e1b`), 20-step smoke, then 2,000 steps, effective batch 32 (mb 4×8),
  E35 text replay 1/4, dev-half selection every 500 steps, seed 42 — the
  E39 recipe. Evaluated once on test non-FR, test FR, the real set and the
  E35 text sets.
- jev-vlm-4b: the E39 sample (sha256-ordered first 200 per family of test
  non-FR = 1,400 rows; reproduces `jev_sample_ids.json` of v7) + the full
  real set (2,586).
- Reported, no gate: accuracy with episode-grouped CI per family; ECE (15
  bins) for jev; paired Δ(A1-V − comparator) with the frozen
  `paired_delta_ci` (1,000 group resamples, seed 42) against the official
  v7 A1-V per-case files, computed post hoc from the per-case outputs.
- Claim rules (from E39): if the CI of Δ(A1-V − SmolVLM2) has upper bound
  < 0 it is declared and there is no "best small visual model" claim; jev
  is labelled `zero-shot` and framed as "an existing ~15× larger model
  without adaptation", never as an equal-footing comparison.
- One kernel (`gjusev/mkshv-e39r2-comparators`): SmolVLM2 trains on GPU 0
  while jev runs on GPU 1. One shot; a comparator failure is recorded and
  never voids the other.
