before this commit; the ensemble numbers quoted during the 2026-10-29 research pass came
from fitting splits only (cal_temperature / cal_policy / the E41-era gui_cal of E43),

## What E51 asks

Can a two-seed ensemble (E47 s42 + s43, probability average) or a weight-average soup
of the same two checkpoints (a) hold the released synthetic gate numbers and (b) make
the real-screens abstention gate claimable — at zero GPU cost, entirely from existing
or locally regenerated per-case outputs?

## Checkpoints (sha256-pinned)

- s42 best.pt `8b166fb995069d0f80f95aec9fd759ef47a72fc0cde1338ca453b8adb6d19452`
- s43 best.pt `afcbeaa45a4c033b5e7d3f033b85fdda2642c0fef78397fcecc5bef53cd83c29`
  (source: Kaggle dataset `mkshv-e47-train`; identical pins already live in
  `kaggle/e48_calib.py`). The released artifact `release/model.safetensors`
  (`ff4a4759…`) is s43 and is the regression bar for every gate.

## Ensemble definition (frozen)

- Members: s42, s43 raw option probabilities per case (as stored in per-case files:
  pre-temperature softmax outputs).
- **Primary: prob-avg** — per case, `p_ens[i] = (p_s42[i] + p_s43[i]) / 2`, then the
  policy temperature applied to `p_ens` via the E42 transform (softmax of log p / T).
- Descriptive-only ablation, never gate-selecting: **logit-avg** (geometric mean,
  renormalised), same pipeline, reported alongside.
- Per-case ids must align across the two seed files (asserted; row counts equal).
- `pred_ens = argmax(p_ens)`; gold asserted identical across seeds per id.

## Fit protocol (E42/E48 verbatim, reused by import from `kaggle/e42_calib.py`)

- `T_ens` = `fit_T` on the **ensemble** `cal_temperature` split (NLL grid 0.50–3.00
  step 0.01, ternary refinement).
- `tau_ens` = `pick_tau` on the **ensemble** `cal_policy` split: smallest grid tau
  (0.30–0.95, step 0.05) whose CP95 upper bound of selective risk ≤ 0.05; none →
  0.95 with `met_target = false`.
- No other hyperparameter exists. The same two-step fit with the same grids is used
  for the screens arm and the soup arm, each on its own fitting split.

## Arm A — synthetic ensemble (runs at freeze+1; pure offline math)

Data: the E48 per-case files for both seeds (`runs/e48/percase_s4*__*.jsonl`).
Fit on `cal_temperature`, `cal_policy`. Held-out, each read ONCE after this commit:
`test_nonfr`, `test_fr`, `testC`, `fresh_ft`, `cord`, `gui`, `task`.

Gates (fail any → arm reads negative; no post-hoc changes):

- **G1 (floor)**: ensemble full accuracy on `test_nonfr` ≥ **0.9488**
  (= released s43 0.9588 − 1.0 pp, pre-registered).
- **G2 (gate holds)**: on `test_nonfr` at `tau_ens`, CP95 upper of selective risk
  ≤ 0.05 AND coverage ≥ 0.90.
- **G3 (no regression vs the RELEASE)**: for every held-out set above, ensemble full
  accuracy ≥ s43 full accuracy − 2.0 pp (same-set comparison from the same per-case
  files; the s42 column and each seed's own published policy numbers are reported
  descriptively but never gate).

## Arm B — screens-domain ensemble gate (contingent; 0 GPU, local CPU)

Run condition: Arm A computed first; Arm B runs regardless of Arm A's verdict (it
targets a different claim).

- Regenerate `gui_cal` probabilities with the E47 checkpoints: the 2,400 rows of
  `data/e43/gui_cal/rows.jsonl`
  (sha256 `97607909bba1b0e97d4b760a3ff1f83a01aea81fae9167cc85c22ab40ba80162`,
  image root `data/e43`, split field already materialised: 1,182 `cal_temperature`
  / 1,218 `cal_policy` by the frozen E43 episode rule in `data/e43/manifest.json`),
  via `scripts/e43_infer.py --ckpt <e47 best.pt> --sha <pin> --upscale 1024`, once
  per seed, on this machine's CPU. Ids asserted equal to the E43 per-case id lists.
  (The stored E43 gui_cal probabilities are E41-era and are NOT reused; precedent
  for per-case regeneration: the E43 CPU/GPU equivalence check.)
- Fit on the ensemble regenerated gui_cal, split by the row `split` field:
  `T_scr` on the 1,182 `cal_temperature` rows (E42 `fit_T`), `tau_scr` on the
  1,218 `cal_policy` rows with **E43's extended grid**
  G = {0.30…0.95 step 0.05} ∪ {0.96, 0.97, 0.98, 0.99, 0.995, 0.999}
  (screens confidence sits high; E43's stated motivation). If no value of G
  qualifies, the frozen outcome is **no feasible gate**: report and stop, the
  screens claim is not made.
- Evaluate ONCE on the E48 held-out `gui` per-case files (offline ensemble of the two
  existing files; these rows were read exactly once by the E48 kernel and are reused
  here as already-computed outputs, E43-precedent; the same `gui` rows also appear
  in Arm A's G3 accuracy table — both uses are pre-registered in this one frozen
  doc, on already-computed outputs, at different operating points).
- **G4 (screens claim)**: held-out real-GUI selective risk CP95 upper ≤ 0.05 at
  coverage ≥ 0.30 at `tau_scr`. Pass → the screens-domain gate becomes claimable for
  the ensemble policy; fail → recorded as measured, claim stays unclaimed.
- Descriptive: risk-coverage curve, and the single-seed screens numbers under the
  same `T_scr/tau_scr` for context.

## Arm C — soup smoke, then soup policy (contingent; 0 GPU, local CPU)

Run condition: checkpoints downloaded and sha-verified.

- **Stage A (smoke)**: uniform weight average of the two pinned state dicts
  (element-wise). Run the soup on the 200 pinned `cal_temperature` ids below
  (CPU inference, U1024 rule). Pass criteria, all three: Spearman ≥ 0.9 between
  soup max-prob and ensemble prob-avg max-prob; argmax agreement ≥ 95% vs the
  ensemble; no NaN/degenerate outputs. Any miss → status `soup_unsound`, a
  documented negative, Stage B does not run.
- Smoke ids: the first 200 sorted ids of `cal_temperature`
  (`e38a-doc_type-cal_temperature-de-00000-base` …
  `e38a-doc_type-cal_temperature-en-00043-base`),
  sha256 of the newline-joined id list:
  `3ca3ed61b01d905c997592f00578c58f2c2fc85af93b3509523f4880446f1d70`.
- **Stage B (soup policy)**: soup per-case on `cal_temperature` + `cal_policy`
  (CPU, ~6,300 inferences), same fit protocol, then held-out reads on the five
  locally-runnable sets only: `test_nonfr`, `test_fr`, `fresh_ft`, `cord`, `gui`
  (~11,200 more CPU inferences; `testC` and `task` rows are not local — they live
  only in the Kaggle bundle — and are excluded from the soup arm; Arm A covers
  them for the ensemble). Gates: G1 and G2 unchanged; **G3 restated for the soup
  over those five sets only** (soup full accuracy ≥ s43 − 2.0 pp per set).
  Total Stage B cost ≈ 17,500 CPU inferences ≈ 5.1 h.

## Claims and release rule

- Claims never come from cal splits. A pass on G1–G3 makes the ensemble a *candidate
  policy artifact*; shipping it (doubling inference, publishing the s42 checkpoint)
  is a product decision requiring the user's GO and a fresh release note — it is NOT
  automatic. A pass on G4 adds a screens-domain claim for whatever artifact ships.
- The E50 blind-gold-audit rule is not triggered: E51 creates no new labels and
  generates no new documents; every row is an already-audited existing split row.

## Cost

0 GPU quota. Arm A: seconds (offline math). Arm B: ~2×2,400 CPU inferences
(~1.05 s/case measured, ≈ 85 min total). Arm C Stage A: 200 CPU inferences +
one smoke; Stage B: ≈ 17,500 CPU inferences (fit + local held-out, ≈ 5.1 h).
