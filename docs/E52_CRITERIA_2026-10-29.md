# E52 — receipt-format generator coverage (criteria frozen 2026-10-29)

Frozen BEFORE any E52 row is generated or any E52 number is computed. The only
pre-freeze measurement is the G0 probe below, which exists to decide whether the
crop arm is part of this experiment at all (pre-registered decision rule, result
recorded verbatim).

## What E52 asks

Is the receipts gap (real CORD 0.734 vs 0.972 for the ~4B zero-shot) partly a
generator-coverage gap? The generator prints only EUR amounts (two decimals,
totals 10–5,000, four clean DejaVu fonts at 14–17 px, `src/mksh_v/gen_e38a.py`)
while CORD is thermal-print IDR with dot-thousands, no decimals, and up to 7
integer digits; the E47 digits family has almost no rows past 4 integer digits
(positions 5–7: 393/119/2 rows). E52 trains on an own receipt-family render
pool (thermal degradation, dot-thousands, comma decimals, 4–8-digit totals) and
asks whether printed-total reading moves on never-read receipt-format documents.

## G0 pre-freeze probe (run 2026-10-29, result recorded verbatim)

`s43` (sha-pinned below) on the 716 CORD-train digit-position rows of
`data/e47/bind/rows.jsonl` (train split only, never val/test), full image with
the U1024 rule vs bottom-40% band crop then U1024
(`scripts/e52_g0_probe.py`, raw output `runs/e52/g0_probe.json`):

- full 0.6006, band 0.5517, delta −4.89 pp (< the pre-registered +10 pp)
- **crop arm DROPPED.** E52 trains and evaluates full-image U1024 everywhere;
  the input rule is unchanged. (Side reading, recorded descriptively: the
  released-lineage seed reads CORD-train digits at 0.60 full-image — the
  perception gap is real and large.)

## Data

- New own receipt-family renders, 12,000–20,000 rows, generated locally
  (Playwright, 0 GPU) riding the existing pair/digit machinery
  (`src/mksh_v/gen_e38a.py` fmt/theme/values, `scripts/gen_e45.py` pairs,
  `scripts/gen_e47.py` digit positions; `scripts/gen_e38c.py` `fmt_idr` defines
  the dot-thousands no-decimal convention). Format families (pre-registered
  strata): IDR dot-thousands no-decimals, comma-decimals, 4–8-integer-digit
  totals, thermal/dot-matrix degraded renders (pixelation, blur, contrast drop,
  JPEG). Digit positions 5–7 coverage is a secondary objective.
- EUR and E47 rows ride byte-identical, sha-pinned (pool comparability for G2).
- The new receipt kind's pool weight and what it displaces from the E47 weights
  dict are frozen in the generator config committed with this document.
- CORD train reused exactly as today (777 receipts, attribution carried,
  `docs/data-licenses.md`).
- Registry: the own-render family row is added to `docs/data-licenses.md`
  BEFORE generation. No new external data.

## Fresh test (never-read, generated after this freeze)

≥ 2,000 receipt-format rows, new templates and seeds, stratified by format
family and integer-digit count (strata frozen in the generator config), read
once by the kernel.

## Gates (fail any → negative; no post-hoc changes)

- **G1 (primary, delta)**: both seeds ≥ **+4.0 pp** over the E47 baseline on
  the same fresh receipt test. The baseline is the sha-pinned E47 checkpoints
  evaluated on that test by the kernel before training; it selects nothing.
  Secondary (descriptive, not gating): absolute accuracy, pass bar referenced
  at the E48-C1 level 0.70, reported target 0.75.
- **G2 (no regression vs E47, exact per-case counts, same seed)**:
  N1 synthetic test non-FR ≤ 2.0 pp; N2 real GUI ≤ 3.0 pp; N3 testC and task
  ≤ 3.0 pp each; EUR fresh_ft (the E48 set — declared here a SECOND read,
  regression guard only) ≤ 2.0 pp; real CORD M4 ≤ 3.0 pp as a frozen
  exact-count guard — no CI, no selection or tuning signal, no headline number.
- **G3 (goal guard, E49 lesson)**: M3 swap and own ≤ 3.0 pp.
- **G4 (render audit, E50 standing rule)**: a blind sample of new renders
  (≥ 30, stratified by family) audited by a vision model against their
  programmatic gold BEFORE the kernel runs; ≥ 28/30 must agree, else the pool
  is regenerated before any training.

## Training

One two-seed T4x2 kernel, init from the pinned E47 checkpoints
(s42 `8b166fb9…`, s43 `afcbeaa4…`) via the `CONFIGS` mechanism, U1024 +
expandable_segments + micro-batch 4 + 800 steps + dev cadence + selection key
identical to E47 (~11k s). Launch after the 2026-10-31 quota refresh, with the
user's GO. Any release requires a separate fresh recalibration experiment
(E42/E48 protocol) that fixes the input rule.
