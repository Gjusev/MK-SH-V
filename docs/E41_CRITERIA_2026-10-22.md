# E41 criteria (FROZEN 2026-10-22, before any data is generated)

## Question

E39 left A1-V at chance on real pixels (E38c real 0.471; CORD
field_threshold 0.394, GUI-Odyssey task_done 0.493) while it wins on
synthetic data; E39-r2 showed the task is solvable on the same real set
(jev-vlm-4b zero-shot 0.785). The E39 error analysis (2026-10-22) points to
the training distribution: synthetic receipts are EUR with two decimals
(CORD is IDR with thousands separators and no decimals) and synthetic
task_done screens carry completion cues real screens do not have.

**E41 asks one thing: with the E39 A1-V recipe unchanged, does adding real,
CC-BY training data improve accuracy on the frozen E38c real evaluation
without losing synthetic or text competence?** Only the training data
changes; architecture, initialisation, steps, batch, learning rates and
image size are E39's.

Declared: the E38c real evaluation set has been inspected (E39 error
analysis). Its errors motivated E41; nothing in E41 is selected, tuned or
trained on it. Selection uses dev splits drawn from the training sources.

## Data (new, training only; generated after this freeze)

Both sources are CC BY 4.0 (`docs/data-licenses.md`; attribution kept in
the dataset card). Private Kaggle dataset `gjusev/mkshv-e41-realtrain`.

- **CORD v2 `train` split** (800 receipts; E38c used `validation`+`test`
  only). Same total-extraction rule as E38c (`cord_total` +
  `parse_id_price` + printed-string check). Per clean receipt TWO
  thresholds, one below and one above the total, each at relative distance
  δ ~ log-uniform[0.001, 0.5] (E38c's distribution), seeds from the receipt
  id. Labels from the ground truth (`total >= thr`). Question templates,
  options and IDR formatting identical to E38c (`fmt_idr`, dot thousands,
  in every language; parity with the frozen eval is kept on purpose).
  Languages en/es/de. group_id = receipt.
- **GUI-Odyssey `task_split` train** COMPLETE episodes (E38c used
  `task_split` test only; the two are disjoint by construction and
  asserted). sha256-ordered, first 1,200 episodes whose two screenshots
  download. Pairs as E38c: final screenshot = true, step k (sha-derived,
  k < n/2) = false; same templates; en/es/de; group_id = episode.
  **No visual verification**: E38c found 65.9 % of COMPLETE finals not
  visually verifiable, so training labels are declared noisy (the
  evaluation keeps its verified labels).
- **real-dev**: 10 % of groups per source by sha256(group_id), used only for
  checkpoint selection. The rest is real-train.
- Generator asserts: labels re-derived from the ground truth, no group in
  two splits, no episode id or CORD image in E38c, row sha256 in a manifest.

## Recipe (E39 A1-V, one change)

C3 checkpoint init (sha-pinned), 2,000 steps, effective batch 32 (8
microbatches × 4), lr 2e-5 backbone / 1e-4 head, warmup 5 %, longest side
1,024 px, E35 text replay on every 4th microbatch, fp16 autocast. **Change:**
microbatch slot `s % 4 == 1` draws from the real-train pool (per step: 2
replay, 2 real, 4 synthetic microbatches). Dev every 500 steps; selection
metric = mean(synthetic dev-half macro, real-dev macro over {CORD, GUI});
tie → higher synthetic dev-half accuracy. Seeds 42 (primary) and 43
(confirmation), one per GPU, in one T4×2 kernel `gjusev/mkshv-e41-train`.

## Evaluation (once, on each seed's selected checkpoint)

E38c real (2,586), synthetic test non-FR (4,200) and FR (1,400), text sets
testC (48) and task (300). Per-case files; gates computed post hoc with the
frozen `paired_delta_ci` (1,000 episode resamples, seed 42) against the
official E39 v7 A1-V per-case files.

## Gates (both seeds must pass each gate)

- **G1 real transfer**: Δ(E41 − E39 A1-V) on E38c real, CI95 lower bound > 0.
  Reported per source (CORD, GUI) and per language.
- **G2 synthetic non-regression**: Δ(E41 − E39 A1-V) on test non-FR,
  CI95 lower bound ≥ −0.02.
- **G3 text**: testC ≥ 0.959 and task ≥ 0.780 (E39 G2 bars).

Verdict: all three → **GO-E41** (real transfer improved by training data);
G1 fails → the gap is not closed by this much real data (reported as such);
G1 passes with G2/G3 failing → improvement with a declared cost.

Reported, no gate: Δ vs jev-vlm-4b (E39-r2 files; zero-shot, ~15× larger;
"matches jev" only if the CI upper bound ≥ 0), Δ vs OCR→MK-SH-1 (v7), ECE.

## Budget and stop rules

Quota checked right before the push; launch only if remaining ≥ 18,000 s
(both seeds run in parallel, measured T4×2 billing ≈ 1× wall). A worker
failure is recorded and does not void the other seed. One shot: any change
after results = a new experiment.
