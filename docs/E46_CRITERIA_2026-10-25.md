# E46 criteria (FROZEN 2026-10-25, before any E46 run)

## Question

E45 (result b6a126f) separated comparison from perception. Two numbers
written in the text are compared at fine gaps (bind dev `cmp_text` under
10 % gap 0.975 / 0.990), the same comparison with the total printed in the
image stays near chance (`num_syn` under 10 % gap 0.622 / 0.617), and the
second digit of the printed total is read at 0.30 / 0.37.

Measured on 2026-10-25, before this file, with no training: the NeoMME
image processor never upscales. An E38a document of 794 × 453 px gives the
same 15 × 25 grid of 32 px patches at `max_side` 1024, 1536 and 2048. Every
E38a and E38b image has its longest side at or below 800 px (E38a 439–794,
E38b 800), and the documents use a 14–17 px body font, so one patch spans
about four digits. This explains why E39's resolution sweep was flat on
synthetic dev (0.936 / 0.932 / 0.932 at 768 / 1024 / 1536): above 794 px
nothing changed.

**E46 asks whether upscaling every image to the full longest side before the
processor makes the printed total readable at fine gaps, without regression
against the released E41 checkpoints.** A second, separate lever raises the
goal weight, because E45's goal swap stopped at 0.735 / 0.803 against a 0.80
gate.

## Input rule (new; applies to training and to every evaluation of an arm)

`upscale(image, S)`: if the longest side is below S, resize by
S / longest side (Lanczos) so the longest side equals S; then the processor
runs with `max_side = S` as before, which still downscales larger images.
Implemented once in `mksh_v.arch_a1v` (`build_batch(..., upscale_to=S)`,
threaded through `evaluate_a1v` and `decide_rows`); the default is off, so
every earlier experiment is unchanged.

Share of images the rule enlarges, measured from the files:

| source | longest side < 1024 | < 1536 |
|---|---|---|
| E38a documents, E38b screens (synthetic) | 100 % | 100 % |
| E41 CORD train | 31 % | 78 % |
| GUI-Odyssey (E41 train, E43 cal) | 0 % | 17–23 % |

## Arms (two arms, two seeds each)

- **U1024**: S = 1024. Large real images are processed exactly as in E45.
- **U1536**: S = 1536. This also raises the cap for large real images from
  1024 to 1536 px, which E39 measured at inference only (real eval
  0.47 → 0.55).
- Init: the E45 checkpoints (s42 `a360c961…`, s43 `c729a142…`), read from the
  output of kernel `gjusev/mkshv-e45-train`, sha-verified.
- Recipe = E45 (800 steps, slot % 4 = synthetic / E41 real / bind / replay,
  AdamW 2e-5 / 1e-4, wd 0.01, warmup + decay, fp16, 700 / 96 tokens, dev every
  200 steps, the same selection key). Bind pool v2 unchanged (dataset
  `mkshv-e45-bind`, rows sha `78c82e21…`).
- Bind weights, changed from E45 on the basis of E45 bind dev only:
  `cmp_text` 0.15 → 0.05 (saturated at 0.98–0.99), `goal` 0.15 → 0.20,
  `goal_match` 0.15 → 0.20 (goal bind dev 0.77 / 0.82). Unchanged:
  `num_syn` 0.20, `num_cord` 0.10, `digits` 0.20, `range` 0.05.

## Memory smoke first (its own push, before any full run)

One kernel per arm in smoke-only mode: 20 steps, seed 42, recording peak GPU
memory (`torch.cuda.max_memory_allocated`) and seconds per step. Rules fixed
here:

- An arm whose smoke fails (out of memory or any error) is `not_run`, and
  that is reported as its result.
- An arm whose projected time (smoke s/step × 800 × 1.15) exceeds its train
  deadline still runs; the deadline stops it and `stopped_at` is reported.
- The full runs are pushed only after the smoke numbers are shown to the user
  and the user gives a GO.

Deadlines: U1024 train 2.5 h, wall kill 3.2 h (as E45). U1536 train 4.0 h,
wall kill 4.8 h.

## Measurements

Same sets and pipelines as E44 and E45 (M1 probe, M2 E38a field_threshold
test, M3 E43 swap + own goal, M4 E38c CORD, N1 synthetic test non-FR, N2 E38c
GUI, N3 testC / task), with the arm's input rule applied everywhere: kernel
evaluation and the CPU inference for M1 and M3 (`scripts/e43_infer.py
--upscale S`). Reported without a gate: bind dev by kind and by relative gap
(under 10 %, 10–50 %, 50 % and above), digits dev by question, probe O and T.

## Success rules (same thresholds as E44 and E45, applied per arm)

- **G1 numbers**: both seeds: probe SYN S ≥ 0.50, L and H ≥ 0.90, and
  M2 ≥ 0.70.
- **G2 goals**: both seeds: M3 swap ≥ 0.80 and own goal ≥ 0.80.
- **G3 no regression, against the released E41 checkpoint of the same seed**:
  N1 drop ≤ 2.0 pp, N2 drop ≤ 3.0 pp, N3 drops ≤ 3.0 pp each.

G1 + G3 or G2 + G3 make that capability a release candidate, pending a
recalibration experiment (E42 protocol, new criteria). If both arms qualify
for the same capability, U1024 is the candidate (cheaper at inference) and
U1536 is reported. The input rule enters the inference contract only through
that release decision. E46 changes no public number by itself.

## Budget and guards

T4×2, one kernel per arm. Quota before E46: 17,126 s of 108,000 s
(refresh 2026-10-31). Each push needs the user's GO: the smoke push has it
(2026-10-25); the full push waits for the smoke report.

## Result (2026-10-25, recorded after measurement; rules above unchanged)

**Smoke** (`gjusev/mkshv-e46-smoke` v1, about 6 min): U1024 completed at a
peak of 9.50 GB allocated / 12.24 GB reserved of 14.56 GB, 7.48 s/step.
**U1536 ran out of memory on its first training step** (14.54 GB in use),
so U1536 is `not_run` by the rule above.

Upscaling made the printed total readable at the level the digits questions
ask: the second digit went from 0.30 / 0.37 to 0.88 / 0.79. Comparison at fine
gaps with the total in the image moved less (num_syn under 10 % 0.62 → 0.72 /
0.66; M2 0.635 / 0.620 → 0.677 / 0.692). The E38a family has a median gap of
2.4 % and 37 % of its rows under 1 %, which needs digits beyond the second; the
digits family asks only the first two digits and the digit count. Goal swap moved
in opposite directions on the two seeds (+4.0 / −4.3 pp) with the higher goal
weight.
