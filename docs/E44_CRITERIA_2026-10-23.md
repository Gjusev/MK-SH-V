# E44 criteria (FROZEN 2026-10-23, before any E44 training row is generated)

## Question

The E44 probe (`docs/E44_PROBE_CRITERIA_2026-10-23.md`, report f539db7) read
**text-number binding** on both E41 seeds: the threshold in the question has no
effect (S = −0.014 … 0.011, even at a 10,000× gap) and a total stated in the
text is not compared (T 0.49–0.54). E43 found the same for goals on
screenshots (goal-swap accuracy 0.12 / 0.135). In both cases the training data
never made the text necessary: synthetic counterfactuals change the image
under a fixed question, GUI rows never change the goal.

E44 asks: does a short fine-tune of the E41 checkpoints on **balanced pairs in
which only the text changes** make the model use the question number and the
goal, without losing what it already does?

## Arm (one arm, two seeds)

- Init: the E41 selected checkpoints (s42 sha e4b4f6f5…, s43 sha 30f2eb42…,
  Kaggle dataset `mkshv-e41-runs`), seed 42 on GPU 0, 43 on GPU 1.
- 800 optimizer steps, E41 recipe otherwise (effective batch 32, microbatch 4,
  AdamW 2e-5 backbone / 1e-4 heads, wd 0.01, 5 % warmup + E39 decay, fp16,
  1024 px, 700/96 tokens).
- Microbatch slots (of 8): 0, 4 synthetic E39 pool; 1, 5 E41 real pool;
  3, 7 E35 text replay; **2, 6 the new bind pool**. A bind microbatch holds two
  complete pairs, so both members of a pair receive gradient in the same
  microbatch. Loss unchanged (cross-entropy over options).
- Dev every 200 steps. Selection: mean of (synthetic dev-half macro, real-dev
  macro, bind-dev accuracy); tie → higher synthetic dev-half accuracy. The
  E44 probe rows, the E43 sets and every test set play no part in selection.

## Bind pool (generated by `scripts/gen_e44.py` after this commit; train splits only)

All images already exist (E38a field_threshold, E41 CORD and GUI-Odyssey
train). Pair weights in the pool: NUM-SYN 0.35, NUM-CORD 0.20, NUM-TEXT 0.10,
RANGE 0.05, GOAL 0.30.

- **NUM-SYN**: every E38a field_threshold **train** image (base, decisive,
  irrelevant). Per image, two pairs; each pair = same image, threshold
  total/g (gold true) and total×g (gold false), question template and number
  format of the row's language. Gap g: one pair log-uniform in [1.005, 1.5]
  (fine), one in [1.5, 1000] (coarse). Deterministic per image.
- **NUM-CORD**: every E41 CORD **train** receipt, same construction, IDR
  format, language rotated over EN/ES/DE by receipt.
- **NUM-TEXT**: half of the NUM-SYN images again, the state extended with
  "The total printed on this document is {total}." (the probe's T sentence,
  same templates), one pair per image from the fine/coarse mix.
- **RANGE**: every NUM-SYN image once: "Which range does the total on this
  document fall into?", four options = four consecutive powers-of-ten bins
  (the true bin at a deterministic random position). Diagnostic of
  perception, trained jointly; singletons, grouped two per pair slot.
- **GOAL**: every E41 GUI-Odyssey **train** episode: its final screen with its
  own goal (gold true) and with the goal of another E41 train episode (gold
  false), drawn deterministically among goals with token Jaccard < 0.5 to the
  own goal. Language rotated EN/ES/DE by episode (state/question templates of
  E41; goals stay in English as in E41).

Bind dev (selection only): the same constructions on E38a field_threshold
**dev** images not in the probe, E41 CORD dev receipts not in the probe, and
E41 GUI dev episodes.

## Success rules (fixed here)

- **Numbers bound (G1)**: M1 on SYN, both seeds: S ≥ 0.50 and L and H accuracy
  ≥ 0.90; and M2 ≥ 0.70 both seeds.
- **Goals bound (G2)**: M3, both seeds: swap accuracy ≥ 0.80 and own-goal
  final-screen accuracy ≥ 0.80.
- **No regression (G3)**: per seed against its own E41 checkpoint: N1 drop
  ≤ 2.0 pp, N2 drop ≤ 3.0 pp, N3 drop ≤ 3.0 pp each.
- Reported, no gate: M1 on CORD, M1 T, M4 against rules 0.594, RANGE dev
  accuracy (perception), per-family test table.

Readings: G1 and G3 → the numeric family is learnable from text-only pairs;
G2 and G3 → goal grounding works on held-out real screens. Failing G3 voids
G1/G2 as release candidates. Any public claim waits for a recalibration
experiment on the E44 checkpoints (E42 protocol, new criteria); E44 changes no
public number by itself. Anything else: reported as measured, no forced
reading.
