# E38a criteria (FROZEN 2026-10-14)

E38a answers one question: **can we generate document decision data whose
labels are correct, whose splits do not leak, and whose answer is only
recoverable from the image?** It covers the three document families of
`docs/design.md`. Screens (`screen_state`, `task_done`, `source_conflict`,
`urgency`) are E38b; conversion of real permissive data (CORD, DocLayNet,
GUI-Odyssey) and eval-only sets are E38c. Each gets its own frozen criteria.

Frozen before any dataset is generated. Development renders while writing the
generator use seed `999` only, are written outside `data/`, and never enter a
split. After freezing, counts, split rules, gate thresholds and outcomes do
not change; anything else needs a new criteria file (`E38a-r2`).

No model is trained in E38a and no Kaggle quota is used.

## Pins

- Renderer: Playwright (Python) 1.64.0, Chromium 156.0.8078.4 headless,
  local Windows machine. HTML set with `page.set_content`, screenshot of the
  page element at device scale factor 1.
- Fonts: embedded as base64 `@font-face` (file `file://` URLs do not load from
  `set_content`, measured). Sources are local TTF files whose SHA-256 is
  written into the manifest; no system font fallback is allowed (the
  generator asserts `document.fonts.check` for every family it uses).
- Python 3.12.2 (venv), mokka-decisions `9e1a226e` (contract only).
- Generator and verifier commits are recorded in the manifest. The verifier
  never imports the generator.

## Families

All questions are in the case language. `state` is a constant per language
("Scanned document page." and translations): it carries no label
information. Labels are computed from the content model, never read back from
pixels.

| Family | Type | Options | Label rule (content model) |
|---|---|---|---|
| `doc_type` | choice | invoice, receipt, contract, form, letter, other | the E37 `derive_doc_type` rules, ported to the HTML content model |
| `field_threshold` | noul (`false`/`true`) | No / Yes | "Is the total on this document at least {thr}?" → `true` iff total ≥ thr (equality is `true`) |
| `form_complete` | choice | complete, missing_required, illegible | required fields are marked `*`; `missing_required` iff any required field is empty; else `illegible` iff any required value is rendered illegible; else `complete`. Optional fields may be empty, never illegible |

`field_threshold` construction (removes the threshold→label shortcut): draw
the threshold from a log-uniform range first, then the label (50/50), then
the total as `thr × (1 ± δ)` with δ log-uniform in [0.001, 0.5] (rounded to
cents; equality cases allowed and labelled `true`). Documents (invoices and
receipts) carry distractor amounts (line items, subtotal, tax) and at least
one distractor lies on the opposite side of the threshold in ≥ 30 % of cases.
Amounts use the case language's number format (EN `1,234.56`; ES/DE/FR
`1.234,56`) and the question uses the same format. Decisive text (totals,
field values) is ≥ 14 CSS px.

## Templates and splits

- A template is a layout skeleton composed from slot variants (header, body,
  footer, table/field style). Visual themes (font family among the pinned
  ones, colours, spacing, small offsets) are variants of an episode, not
  templates. Each family has ≥ 24 templates, each class/label reachable from
  every template where the family allows it.
- Split keys are assigned **before** any variant is rendered:
  templates → `train` / `heldout` / `test` by stratified sha256 order
  (≈ 60 / 20 / 20 %, each class present in each part; extends
  `stratified_template_split`). `heldout` templates feed `dev`,
  `cal_temperature` and `cal_policy`, which are episode-disjoint from each
  other. Test templates appear in no other split.
- An episode (= `group_id`) is one content draw on one template in one
  language. All its variants and counterfactuals inherit its split.
- Counterfactuals (`field_threshold`, `form_complete`): a share of episodes
  get a **decisive** variant (minimal content change that flips the label:
  total moved across the threshold; one required field emptied, filled or
  made illegible) and an **irrelevant** variant (theme/offset change, or an
  optional field changed) that keeps it. `doc_type` gets irrelevant variants
  only (declared).

## Counts (per family, cases including counterfactual variants)

| split | EN | ES | DE | FR | total |
|---|---|---|---|---|---|
| train | 1000 | 1000 | 1000 | – | 3000 |
| dev | 100 | 100 | 100 | – | 300 |
| cal_temperature | 150 | 150 | 150 | – | 450 |
| cal_policy | 150 | 150 | 150 | – | 450 |
| test | 200 | 200 | 200 | 200 | 800 |

FR exists only in `test` (evaluation-only language). Labels are balanced
exactly (±1 case) within every split × language: 1/6 per class for
`doc_type`, 1/2 for `field_threshold`, 1/3 for `form_complete`.

## Gate (all must hold → PASS)

**G1 Independent verifier** (`scripts/verify_e38a.py`, does not import the
generator). Input: the rows, the rendered HTML/DOM-text sidecars and the PNGs.

- (a) every gold label re-derived from the rendered DOM text/structure with
  the verifier's own parser equals the row label (100 %);
- (b) no `group_id` or template in two splits; test templates absent
  elsewhere; `dev`/`cal_*` templates absent from `train`;
- (c) every counterfactual shares split and `group_id` with its base;
  decisive variants flip the re-derived label, irrelevant ones keep it;
- (d) counts and balance exactly as in the table (±1 per class);
- (e) every PNG's SHA-256 matches the manifest; every row validates against
  the `mokka_decisions` contract;
- (f) no `state`, `question` or option text contains the decisive value
  (the total for `field_threshold`; field values for `form_complete`).

**G2 Text-only leak test.** A text-only baseline that sees `state`,
`question` and options but no image (multinomial naive Bayes over word
tokens, plus the question threshold binned into deciles as tokens), trained
on `train` and evaluated on `dev ∪ cal_temperature ∪ cal_policy`: accuracy ≤
majority rate + 0.05 for every family. `test` is not used. If it fails, the
generator leaks the label through text: fix the generator under a new
criteria version; the threshold is not relaxed.

**G3 Determinism.** Re-rendering 50 sampled cases per family (fixed sample
seed 7) on the same machine reproduces byte-identical PNGs.

Contact sheets (one per family and language) are produced for the user's
visual review; they are not a gate.

## Outcomes

- `PASS` iff G1, G2 and G3 hold → E38b (screens) may start after user review.
- `FAIL` otherwise, with the failing check and evidence in `docs/status.md`.

Data stays local (`data/`, git-ignored) with manifests and SHA-256. Uploading
to a private Hub dataset is a separate step that needs the user's GO and an
`HF_TOKEN` secret; it is not part of this gate.
