# E43 criteria (FROZEN 2026-10-23, before any E43 data is generated or measured)

## Question

E42 gave one claimable abstention set (synthetic test non-FR) and none on real
images. On real screenshots (E38c GUI, n = 2,010) the synthetic-fitted policy
(T = 1.5455 / 1.2929, τ = 0.55) keeps 98.3 % of cases with 16.7 / 21.3 %
selective risk: the models are confidently wrong there.

**E43 asks whether a screens-domain temperature and gate, fitted on fresh real
GUI calibration episodes, bring held-out real-GUI selective risk under the 5 %
budget (CP95 upper bound), and how much coverage survives.** It is post hoc on
the two E41 checkpoints: no retraining, no change to any weight.

A pre-registered diagnostic is added because of an observation made while
preparing E43 (2026-10-23, commit `f57f77b`): the demo's showcased screenshot
(final step of train episode 4884755305395394) gets *true* at 0.999 both with
its own goal and with an unrelated goal. E41 training and E38c evaluation both
contrast an early and the final screenshot **of the same goal**, so neither
tests whether the model reads the goal. E43 measures it (goal-swap set below).

  `30f2eb429c5b25dca00e1ef53fd509232997c34799a5a22fa1c77200619c3819`

## Pipeline (unchanged from E42)

`evaluate_a1v`, fp32, batch 16, longest side 1,024 px, 700/96 tokens, run on
CPU by `scripts/e43_infer.py`. Equivalence with E42's GPU run, measured before
freezing on the first 32 E38c GUI rows, seed 42: max |Δp| = 9.0e-6, 32/32
identical predictions. The held-out GUI evaluation therefore reuses E42's
per-case files (`runs/e42-calib/percase_s4{2,3}__gui.jsonl`, raw probabilities);
E38c is not re-run and is never used to fit or choose anything.

## Data (generated by `scripts/gen_e43.py` after this commit)

Source: GUI-Odyssey `task_split` **train**, CC BY 4.0, the same source and
licence row as E41 (`docs/data-licenses.md`), used here for calibration only.

- Candidates: the E41 procedure verbatim (stream `split="all"`, keep
  task_split-train episodes whose last action is COMPLETE, first 3,600 in
  stream order, sorted by the sha256 of the row without `steps`).
- Exclusions, asserted: every E41 episode (train and dev, 1,200), every E38c
  episode, every task_split test episode.
- Take the next **400** fetchable episodes in that sorted order. Rows are built
  exactly as E41 (`neg` = step k, k = sha256(eid) mod ⌊n/2⌋, gold *false*;
  `fin` = last step, gold *true*; EN/ES/DE templates): 2,400 rows.
- Split by episode, rule fixed here: `int(sha256("e43|" + eid)[:8], 16) % 2`
  → 0 = `cal_temperature`, 1 = `cal_policy` (≈ 1,200 rows each).
- `swap` (diagnostic only, never used to fit): for each of the 400 episodes,
  its `fin` screenshot with the goal of the next episode in sorted order whose
  goal text differs, English only, gold *false*: 400 rows. Caveat declared in
  advance: two different goals can overlap in content, so some swap labels may
  be wrong; the set is read as an indicator, not a benchmark.

## Protocol

Per seed, independently:

1. **T_screens**: NLL on `cal_temperature`, grid 0.50 to 3.00 step 0.01 plus
   ternary refinement (E42's procedure).
2. **τ_screens**: the smallest value on the grid G whose `cal_policy` CP95
   upper bound of selective risk at T_screens is ≤ 0.05.
   G = {0.30, 0.35, …, 0.95} ∪ {0.96, 0.97, 0.98, 0.99, 0.995, 0.999}.
   The extension above 0.95 is the only change to E42's grid. Its motivation
   is E42's published headline that 98.3 % of real GUI cases sit above 0.55;
   no other E38c GUI number was read for this design.
   If no value of G qualifies, the outcome is **no feasible gate**: the
   screens policy abstains on every real screenshot, and this is reported as
   the result.
3. **Held-out**: E38c GUI (2,010) at (T_screens, τ_screens). Report coverage,
   accepted n, errors, selective risk, exact two-sided Clopper-Pearson 95 %.
   E42's operating point is reported next to it as the baseline.

## Claim rule (unchanged in kind from E42)

E38c GUI is **claimable** iff its CP95 upper bound at (T_screens, τ_screens) is
≤ 0.05 for BOTH seeds. Coverage is always reported with the claim; a claim
with coverage below 10 % is labelled "claimable, not useful".

## Diagnostics (reported, no gate)

- Goal grounding: accuracy on `swap` at T_screens, and the share of swap rows
  answered *true* with p ≥ τ_screens. **Pre-registered reading:** if swap
  accuracy is below 0.5 for both seeds, the model does not use the goal text
  for this question, and the public claim "task completion over screenshots"
  is narrowed to "end-of-task screen detection" in README and model card,
  whatever the gate result.
- Episode-clustered bootstrap (1,000 resamples, seed 42) of held-out selective
  risk at the chosen τ, because the six rows of an episode are correlated and
  Clopper-Pearson assumes independence (same convention as E42; this is a
  sensitivity check, not the claim).
- AUROC of max calibrated probability for correct vs wrong on `cal_policy`
  (does confidence rank errors at all).
- Risk-coverage curve of `cal_policy` (fitting split, in-sample).

## Out of scope

CORD receipts (E44). The synthetic policy (E42) is unchanged. A screens policy
enters `inference-policy.json` only by a separate release decision after the
report, and only if the claim holds.

## Budget and order

≈ 2.4 h. Order: commit this file → generate data → commit the generator and
manifest → inference → report. The report script reads only the files named
