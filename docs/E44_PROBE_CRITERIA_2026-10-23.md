# E44 probe criteria (FROZEN 2026-10-23, before any probe row is generated or run)

## Why a probe first

E42's per-family table shows the synthetic `field_threshold` family ("is the
total on this document at least X") at chance on the held-out test:
0.507 / 0.510 (E41 checkpoints; the synthetic-only E39 model reached 0.597).
Real receipts are near chance too (CORD 0.550 / 0.602). E43 showed that on
screenshots the model ignores the goal text. Three mechanisms fit:

1. **Perception**: the printed total is not read from the pixels.
2. **Comparison**: it is read, but not compared with the number in the question.
3. **Text-blindness**: the question number is ignored, whatever the image.

A training run (E44 proper) should target the right one. This probe separates
them with no training, on train/dev data only, local CPU, both E41 seeds
(sha-verified, pipeline of `scripts/e43_infer.py`).

## Sets (generated by `scripts/gen_e44_probe.py` after this commit)

- **SYN**: `data/e38a/field_threshold` **dev** split, `cf_role == "base"`,
  languages EN/ES/DE, first 120 in file order. Total = the row's `total`
  field (the value the generator rendered as the document total).
- **CORD**: `data/e41/cord` **dev** split (E41 selection split, never trained
  on), English rows, first 60 receipts in file order, both original sides.
  Total = `gt_total_value`.

## Conditions, per document (the image never changes)

- **O**: the original question(s), original gold.
- **L**: threshold = total / 100, gold *true*.
- **H**: threshold = total × 100, gold *false*.
- **T**: the original question(s), with the sentence "The total printed on this
  document is {total}." appended to the state ({total} in the document's own
  format: `fmt_amount` for SYN, the ground-truth printed text for CORD),
  original gold.

Thresholds in L/H use the question's own number format (`fmt_amount` for SYN,
`fmt_idr` for CORD). L and H differ by a factor of 10,000: no reading of digits
is needed, only the order of magnitude.

## Measures

Per set and seed: accuracy in each condition; text sensitivity
S = mean over documents of p(true | L) − p(true | H), paired by document
(1 = the question number drives the answer, 0 = it is ignored).

## Readings (fixed here)

- **R1, magnitude read**: L/H accuracy ≥ 0.90 on a set for both seeds → the
  page total is read at least coarsely and the question number is used; the
  failure in O is fine-grained (digit-level). E44 targets fine reading.
- **R2, question number ignored**: S < 0.10 on a set for both seeds. Then T
  decides:
  - T accuracy ≥ 0.90 → numbers stated in text are compared correctly; the page
    total is not reaching the decision. E44 targets **perception**.
  - T accuracy < 0.70 → even a stated total is not compared. E44 targets
    **text-number binding** (training pairs where only the question changes).
- Anything else: reported as intermediate, with the numbers, no forced reading.

## Scope

Exploratory diagnostic: no claim is made from it, no public number changes.
Rows: SYN 120 × 4 = 480, CORD 60 × (2 O + L + H + 2 T) = 360, per seed.
