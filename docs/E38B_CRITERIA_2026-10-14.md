# E38b criteria (FROZEN 2026-10-14)

E38b answers one question: **can we generate screen-decision data whose labels
are correct, whose splits do not leak, and whose answer is only recoverable
from the image (or from the image-vs-text comparison)?** It covers the four
screen families of `docs/design.md`: `screen_state`, `task_done`,
`source_conflict`, `urgency`. Documents were E38a (PASS); conversion of real
permissive data (CORD, DocLayNet, GUI-Odyssey) and eval-only sets remain E38c.

Frozen before any dataset is generated. Development renders while writing the
generator use seed `999` only, are written outside `data/`, and never enter a
split. After freezing, counts, split rules, gate thresholds and label rules do
not change; anything else needs a new criteria file (`E38b-r2`).

No model is trained in E38b and no Kaggle quota is used.

## Pins

- Renderer: Playwright (Python) 1.64.0, Chromium headless, local Windows
  machine, same `Renderer` harness as E38a (`scripts/gen_e38a.py`): HTML via
  `page.set_content`, screenshot of the `#page` element, device scale 1.
- Fonts: embedded base64 `@font-face`, same pinned DejaVu set (SHA-256 in the
  manifest); the generator asserts `document.fonts.check` per family.
- Python 3.12.2 (venv), mokka-decisions `9e1a226e` (contract only).
- Generator and verifier commits recorded in the manifest; the verifier never
  imports the generator. Urgency is a 5-option choice (`target_kind=single`,
  options lowest first) because the contract has no `score` kind; ordinal MAE
  is an evaluation metric, not a contract field.

## Families

Questions are in the case language. Screens are fake application pages
(app brand, chrome, localized UI strings); every case carries `data-k` markers
so the verifier re-derives labels with its own HTML parser.

| Family | Type | Options | Label rule (content model) |
|---|---|---|---|
| `screen_state` | choice | success, error, loading, needs_input, blocked | exactly one state component present: success = confirmation block with check glyph (`scheck`); error = block with error code and retry button; loading = spinner block with ≥ 2 skeleton rows; needs_input = form with ≥ 1 empty required input and submit; blocked = overlay with lock glyph and no retry button. Two kinds present = structure failure |
| `task_done` | noul `false`/`true` | No / Yes | the goal text names one quoted token; the task-list row whose `tname` contains that token shows `done-mark` → `true`, `todo-mark` → `false`; exactly one matching row, else structure failure |
| `source_conflict` | choice | agree, conflict | the state text contains `Field: value.` claims; compare each claimed field against the DOM value with the same `data-f`: any mismatch → `conflict`, none → `agree`. Field names and value pools are discrete and localized |
| `urgency` | choice 1–5 (ordered) | 1..5 | `U = 1 + img + txt`, no clamping: `img` = 0 no banner, 1 warning banner (`warnbanner`), 2 error banner (`error`), 3 blocked overlay; `txt` = 1 iff the ticket states a deadline ≤ 4 h (else 0). Impact word in the text is decoration (drawn independently); only the deadline field carries `txt` |

Anti-shortcut rules (freeze the draw order):

- `task_done`: the goal is drawn first, independent of the label; the label is
  50/50; the goal row's mark is set to the label; the other 2–4 rows are
  random. The goal appears in `state` (quoted token), never the answer.
- `source_conflict`: text claim values are drawn from the same pools for both
  classes; conflict is realized only in the image (a rendered value changed to
  a different pool value). The conflicting field is chosen uniformly among the
  claimed fields, so the text alone cannot identify a conflicting field.
- `urgency`: `U` is drawn first and balanced; the `(img, txt)` decomposition
  is uniform among those reaching `U`; impact wording and distractor sentence
  are drawn independently of `U`. The banner is never described in text.
- `screen_state`: the state component carries a localized message generated
  per case; the message never appears in `state`, `question` or options.

## Templates, apps and splits

- A template is a layout skeleton `scr-c{chrome}l{layout}p{panel}`:
  chrome ∈ 0..3 (topbar / sidebar / tabs / card), layout ∈ 0..2, panel
  style ∈ 0..1 → 24 per family. Themes (font among the pinned ones, colours,
  spacing, offsets) are variants of an episode, not templates.
- The app is one of 4 fake brands (language-neutral names, localized chrome
  strings). The **split key is the `(app, template)` pair** — 96 pairs per
  family, assigned before any variant by stratified sha256 order:
  19 → test, 19 → heldout, 58 → train. Declared limitation: this yields
  unseen app+template combinations but not an unseen-app axis with seen
  templates; real unseen-app evaluation comes from GUI-Odyssey in E38c.
- `heldout` pairs feed `dev`, `cal_temperature` and `cal_policy`, which are
  episode-disjoint from each other. Test pairs appear in no other split.
- An episode (= `group_id`, `e38b-{fam}-{split}-{lang}-{g:05d}`) is one
  content draw on one pair in one language; its variants inherit the split.
- Counterfactuals (`task_done`, `source_conflict`, `urgency`): decisive
  variant flips the label with the minimal change (goal row mark; one rendered
  value matches/differs; banner present/absent or deadline value); irrelevant
  variant keeps it (theme change, a non-goal row mark, an unclaimed field
  value, the impact wording). `screen_state` gets irrelevant variants only
  (declared), realized as a theme change.

|---|---|---|---|---|---|
| train | 1000 | 1000 | 1000 | – | 3000 |
| dev | 100 | 100 | 100 | – | 300 |
| cal_temperature | 150 | 150 | 150 | – | 450 |
| cal_policy | 150 | 150 | 150 | – | 450 |
| test | 200 | 200 | 200 | 200 | 800 |

FR exists only in `test`. Labels balanced exactly (±1 case) within every
split × language: 1/5 per class for `screen_state` and `urgency`, 1/2 for
`task_done` and `source_conflict`. Total E38b: 20 000 cases.

## Gate (all must hold → PASS)

**G1 Independent verifier** (`scripts/verify_e38b.py`, no generator import,
own HTML parser): input = rows, HTML sidecars, PNGs.

- (a) every gold label re-derived from the rendered DOM plus the row's
  `state`/`question` text (own parser, own field-value table) equals the row
  label (100 %); structure violations (two state kinds, zero or several
  matching task rows, unknown claimed field) are failures;
- (b) no `group_id` and no `(app, template)` pair in two splits; test pairs
  absent elsewhere; `dev`/`cal_*` pairs absent from `train`;
- (c) every counterfactual shares split and `group_id` with its base; decisive
  variants flip the re-derived label, irrelevant ones keep it;
- (d) counts and balance exactly as in the table (±1 per class);
- (e) every PNG's SHA-256 matches the manifest; every row validates against
  the `mokka_decisions` contract;
- (f) text-leak checks: `screen_state` message strings absent from row text;
  `task_done` option texts carry no status words; `source_conflict` option
  texts carry no field values; `urgency` question/options carry no impact
  words or banner names; user-visible text contains no `data-k`, `<img>`,
  `<doc>`, `<row>`, `<eos>` or `[O\d+]` marker tokens.

**G2 Text-only leak test.** Multinomial naive Bayes over word tokens of
`state`, `question` and options (threshold-like numbers binned into deciles),
trained on `train`, evaluated on `dev ∪ cal_temperature ∪ cal_policy`:
accuracy ≤ majority rate + 0.05 for every family. `test` is not used. If it
fails, the generator leaks through text: fix under a new criteria version;
the threshold is not relaxed.

**G3 Determinism.** Re-rendering 50 sampled cases per family (sample seed 7)
reproduces byte-identical PNGs.

Contact sheets (one per family and language) are produced for the user's
visual review; they are not a gate.

## Outcomes

- `PASS` iff G1, G2 and G3 hold → E38c (real permissive data) may start after
  user review.
- `FAIL` otherwise, with the failing check and evidence in `docs/status.md`.

Data stays local (`data/`, git-ignored) with manifests and SHA-256. Uploading
to a private Hub dataset is a separate step needing the user's GO.
